## 一、项目定位

### 1.1 要解决的问题

我们在自己背单词时，遇到过三件很具体的事。

第一，倒计时让人分心。屏幕上跳动的秒数会把注意力从词义拉走，答错时最先想到的不是"我为什么错"，而是"来不及了"。

第二，答错只得到正确答案。多数产品把错题标红、给出释义，然后进入下一题。学习者知道自己错了，但不知道自己错在哪一类：是词性没分清，是形近词混了，还是固定搭配没记住。

第三，离开网络就学不了。词库、例句、复习计划都在服务器上，地铁、教室、老旧的平板电脑，任何一个环节断网，学习就中断；学习记录也不在自己手里。

### 1.2 我们做的东西

微光港是一个可以装进浏览器的英语练习站。打开网址就能用，不需要注册；把它添加到桌面或主屏后，断网也能完整练习。

产品用"港口点亮星球"的叙事把六个训练站串成一条航线：

| 训练站 | 模块 | 主要内容 |
| --- | --- | --- |
| 微光港 | 词汇 | 释义、拼写、听音选词、看图认词；5805 词分级词库 |
| 语法花园 | 语法 | 5 大分支、15 个知识节点、30 道判断题 |
| 桥梁工坊 | 句子 | 4 道长难句拼图、4 道翻译对决 |
| 星际电台 | 听力 | 8 段听写、10 个生活场景共 51 组问答 |
| 灵感工作室 | 写作 | 4 道句子排序、4 道改错 |
| 故事图书馆 | 阅读 | 3 章原创叙事、12 道考点题 |

完成一关得到星级与星尘，星尘灌注成星球能量，星球共 10 个成长阶段。学习数据、错题、复习计划全部保存在本机浏览器。

### 1.3 面向谁

主要使用者是小学高年级到大学阶段的英语自学者，以及需要控制屏幕时间、希望数据留在本机的家长和教师。四条学习路线（小学、初高中、进阶、四六级）按课程大纲划分内容范围，同一套引擎服务不同学段。

使用场景集中在课后碎片时间、通勤与弱网环境、以及不方便注册账号的公共设备。

## 二、主要创新

### 2.1 错因先于答案：把一次错误变成一次针对性讲解

**原有问题。** 答错只显示正确答案，学习者得到的是一次判定，不是一次教学。

**我们的做法。** 判定之后先做错因归因。系统按 10 类错因（时态、主谓一致、冠词、介词、词义辨析、词形、从句、拼写、听力细节、通用）判断这一题为什么错，再给出对应规则讲解，并从 48 组形近词对比卡中匹配一张最接近的卡片。错题写入本机错题本：同一题重复答错只累加次数，答对后自动移出；成长图谱按最近答错时间列出题干、错因与正确答案，点一条即可回到那道题重练。

**实际效果。** 六个模块共用同一套错因卡，听力选词也走同一条路径。错题从"答完即消失"变成可回看、可验证的记录。相关代码在 `src/engine/errorRouting.ts` 与 `src/components/game/ErrorCard.tsx`，并有单元测试覆盖归因规则。

### 2.2 去掉倒计时的激励设计

**原有问题。** 打卡类产品普遍用倒计时制造紧迫感，短期提升了答题速度，长期消耗学习动机。

**我们的做法。** 取消倒计时，改成"连击蓄能"：连续答对累积连击，每 5 连击点亮一次双倍经验，答对消耗蓄能、答错中断。节奏由学习者自己掌握，压力来自"要不要再答一题"，而不是"还剩几秒"。

**实际效果。** 单局时长从固定 3 分钟变为由作答节奏决定；连击上限与最佳连击进入成长数据，成为可回看的进步指标。

### 2.3 离线优先与本地数据

**原有问题。** 学习工具依赖账号与网络，弱网环境下不可用，学习数据存放在平台服务器。

**我们的做法。** 整站 PWA 化。Service Worker 预缓存 113 项资源（约 3.2 MB），首屏与六个模块离线可用；词库按学习路线分片，进入词汇模块时按需下载（约 2.2 MB），完成后断网可完整练习。学习进度、错题、复习计划写入本机 IndexedDB，无账号体系、无遥测埋点。语音识别使用浏览器本地能力，不采集音频。

**实际效果。** 安装到桌面后断网刷新仍可答题；清除浏览器数据会同时清除学习记录，这一点在设置页明确写出，不做隐藏。

### 2.4 叙事化的学习路径

**原有问题。** 练习产品常把六个模块做成六个互不相干的入口，学习者缺少"走到哪里了"的整体感。

**我们的做法。** 用一条暮色海港航线把六个站串起来：每站有独立场景插画与章节目标，完成后点亮灯塔、掉落星尘；星尘在工坊灌注成星球能量，推动 10 个阶段的星球成长。成长不是抽象的进度条，而是一张可以回看的地图。

**与既有成果的差异。** 与打卡型背词产品相比，差异在错因教学与本地化数据；与普通教育网页相比，差异在完整的游戏化循环与离线工程能力。交互、算法与全部代码由团队实现，第三方资源见《第三方资源说明》。

## 三、技术实现

### 3.1 技术路线

React 18 + TypeScript 5.6 + Vite 6，状态层 Zustand，本地持久化 Dexie（IndexedDB），图表 ECharts 按需加载，离线能力由 Service Worker 提供，部署在 GitHub Pages。

代码组织按"引擎—数据—组件"分层：`src/engine` 放判分、间隔重复、难度校准、错因归因等纯函数；`src/data` 放词库、语法、句子、听力、写作、阅读等内容；`src/components` 按模块拆分。纯函数层便于单元测试，也便于替换内容而不动交互。

### 3.2 学习机制

**自适应难度。** 依据正确率与作答用时，在 5 个难度档之间动态校准，目标是把正确率维持在"跳一跳够得着"的区间。每轮答题的难度变化会记录成一条曲线，在成长图谱里可回看。

**间隔重复。** 简化版 SM-2：答对后间隔按 1、3、7 天递增，上限 30 天；连续 3 次答对记为掌握。词林按记忆健康度分档，到期词自动进入复习队列，首页显示"今日到期"数量。

**选项顺序去偏。** 静态题库的正确项原本长期停在第一个位置，学习者可以靠位置记忆连对。现在所有选择题按题目 id 做确定性重排：同一题刷新后顺序不变，但正确项在题目之间分散。判定与错题记录仍用原始下标。逻辑在 `src/engine/optionOrder.ts`。

### 3.3 内容生产与校验

词库来自 ECDICT（MIT），构建期转换为五级分片，共 5805 词，5729 词配有 Tatoeba 真实语料例句，词性覆盖率 99.07%。语法、句子、听力、写作、阅读为团队原创内容。

内容不靠人工目测。`scripts/validate-content.mjs` 校验词库结构、词性覆盖与题目字段完整性；`src/data/grammar.test.ts` 用分词与 Jaccard 相似度检查"例句不能被直接抄成答案"；`src/data/reading.test.ts` 检查选项标签不得包含正确答案。这些测试把内容质量问题变成可重复执行的检查。

### 3.4 工程质量

`npm run validate` 是一条发布门禁：类型检查、lint、524 项 Vitest 单元与组件测试、21 项 Python 内容测试、构建、产物体积预算（初始 JS ≤ 409,600 B，当前 399,279 B，gzip 137,120 B）、21 项 Node 契约测试（Service Worker、离线契约、PWA 资源、设计一致性、启动兜底）、内容校验。任何一项失败都不能发布。

GitHub Actions 在每次推送后执行同一套检查并部署 Pages。

### 3.5 可用性与无障碍

六个模块的选择题支持数字键 1–N 选答、Enter 确认或重答；选项显示数字键帽。图表提供原生数据表替代视图。练习页在 1920×1080 与 1440×900 下可一屏显示完整题目，不需要滚动。深浅色主题跟随系统并可手动切换，练习页与首页使用同一套语义色令牌。

## 六、应用与传播价值

**即开即用。** 免安装、免注册，浏览器打开即可学习；Chrome / Edge 可一键安装到桌面，iOS 通过"分享 → 添加到主屏幕"安装，安装后以独立窗口运行。

**适配弱网。** 离线包与 PWA 缓存让网络条件有限的学校与家庭也能使用，减少对机房带宽的依赖。

**数据留在本机。** 无账号、无上传、无埋点。对隐私敏感的用户和未成年人使用场景，这一点比功能数量更重要。

**可继续扩展。** 学段路线、词库、章节内容都是配置化数据，增加学段或语种不需要改交互层；内容校验脚本保证扩展时不破坏既有质量。

**可传播。** 链接自带 1200×630 分享预览卡；移动端自适应，适合课堂演示与扫码体验。
