# 微光港：英语星图

作品编号 452953 ｜ 自主选题类（七）智慧教育与科普创作类 ｜ 方向（2）虚拟实验、教育游戏和智能学习工具

成果形态：Web 应用（PWA，可安装、可离线）　访问地址：https://runner-cpu.github.io/FlowVocab/

## 一、作品定位

### 1.1 起因

这个作品来自我们背单词时反复遇到的三个场景。

第一个场景是倒计时。屏幕右上角的秒数一直在跳，读到第三个选项时已经开始算还剩几秒，最后往往是凭印象点一个。答错之后先想到的是"太慢了"，而不是"这个词我到底哪里没弄明白"。

第二个场景是答错之后只显示正确答案。红色标出正确项，释义列在下面，点下一步。下一次遇到同一个词，错的地方还是错的，因为从来没人告诉我们错的是词性、是搭配，还是把形近词看串了。

第三个场景是断网。宿舍断网、地铁进隧道、教室的旧平板连不上网，词库和复习计划都在服务器上，学习就断了。学习记录也不在自己手里。

我们想做的东西很具体：把这三件事各解决一次。

### 1.2 做成了什么

微光港是一个打开网址就能用的英语练习站，不用注册。添加到桌面或主屏之后，断网也能完整练习。

六个训练站串成一条"港口点亮星球"的航线：

| 训练站 | 模块 | 内容 |
| --- | --- | --- |
| 微光港 | 词汇 | 释义、拼写、听音选词、看图认词，5805 词分级词库 |
| 语法花园 | 语法 | 5 大分支、15 个知识节点、30 道判断题 |
| 桥梁工坊 | 句子 | 4 道长难句拼图、4 道翻译对决 |
| 星际电台 | 听力 | 8 段听写、10 个生活场景共 51 组问答 |
| 灵感工作室 | 写作 | 4 道句子排序、4 道改错 |
| 故事图书馆 | 阅读 | 3 章原创叙事、12 道考点题 |

每完成一关得到星级和星尘。星尘在工坊里灌注成星球能量，星球有 10 个成长阶段。学习记录、错题、复习计划都写在本机浏览器里。

### 1.3 给谁用

主要是三类人：小学高年级到大学阶段的英语自学者；希望控制屏幕时间、又不想把孩子的学习数据交出去的家长；网络条件一般、或者机房设备比较旧的学校。

四条学习路线（小学、初高中、进阶、四六级）按课程大纲划分了内容范围，同一套引擎服务不同学段。使用场景集中在课后碎片时间、通勤路上，以及不方便注册账号的公共设备。

## 二、四个主要创新

### 2.1 先讲错因，再给答案

过去的做法是判定对错，然后翻页。我们的做法是判定之后先归因。

系统按 10 类错因判断这一题错在哪里：时态、主谓一致、冠词、介词、词义辨析、词形、从句、拼写、听力细节，以及兜底的通用类。归因之后给出对应的规则讲解，再从 48 组形近词对比卡里找一张最接近的，放在同一屏里对照。错题写进本机错题本：同一题重复答错只累加次数，答对之后自动移出；成长图谱按最近答错时间列出题干、错因和正确答案，点一条就回到那道题重练。

六个模块共用同一张错因卡，听力选词也走这条路径。错题从"答完就消失"变成可以回看、可以验证的记录。

实现上，归因规则是纯函数（`src/engine/errorRouting.ts`），错因卡的渲染独立于模块（`src/components/game/ErrorCard.tsx`），两条都有单元测试覆盖。

### 2.2 把倒计时拿掉

打卡类产品喜欢用倒计时制造紧迫感。短期确实能提升答题速度，长期消耗的是学习动机——你会开始躲着它。

我们把倒计时删掉，换成"连击蓄能"：连续答对累积连击，每 5 连击点亮一次双倍经验；答对消耗蓄能，答错中断。节奏由学习者自己掌握，压力来自"要不要再答一题"，而不是"还剩几秒"。

单局时长因此从固定的 3 分钟变成由作答节奏决定。连击上限和最佳连击进入成长数据，成为可以回看的进步指标。

### 2.3 离线优先，数据留在本机

整站做了 PWA。Service Worker 预缓存 113 项资源（约 3.2 MB），首屏和六个模块离线可用；词库按学习路线分片，进词汇模块时按需下载（约 2.2 MB），下载完成之后断网也能完整练习。学习进度、错题、复习计划写进本机 IndexedDB，没有账号体系，没有遥测埋点。语音识别用浏览器自带的能力，音频不上传。

安装到桌面后断网刷新仍然可以答题。清除浏览器数据会同时清掉学习记录，这一点在设置页写得很清楚，没有藏起来。

### 2.4 把六个入口连成一条航线

练习产品常把模块做成六个互不相干的入口，学到最后不知道自己走到哪儿了。

我们用一条暮色海港的航线把六站串起来：每站有独立的场景插画和章节目标，完成后点亮灯塔、掉落星尘；星尘在工坊里灌注成星球能量，推动星球走过 10 个阶段。成长不是一根抽象的进度条，而是一张可以回看的地图。

和打卡型背词产品比，差别在错因教学和本地数据；和普通的教学网页比，差别在完整的游戏化循环和离线工程能力。交互、算法和全部代码由团队完成，第三方资源在另一份说明里逐项列明。

## 三、怎么实现的

### 3.1 技术路线

React 18 + TypeScript 5.6 + Vite 6，状态层用 Zustand，本地持久化用 Dexie（IndexedDB），图表用 ECharts 并按需加载，离线能力由 Service Worker 提供，部署在 GitHub Pages。

代码按"引擎—数据—组件"分层。`src/engine` 放判分、间隔重复、难度校准、错因归因这些纯函数；`src/data` 放词库、语法、句子、听力、写作、阅读；`src/components` 按模块拆分。纯函数层好测试，也方便以后换内容而不动交互。

### 3.2 三个学习机制

**自适应难度。** 根据正确率和作答用时，在 5 个难度档之间动态校准，目标是把正确率维持在"跳一跳够得着"的区间。每轮的难度变化记录成一条曲线，在成长图谱里可以回看。

**间隔重复。** 简化版 SM-2：答对后间隔按 1、3、7 天递增，上限 30 天；连续 3 次答对记为掌握。词林按记忆健康度分档，到期词自动进入复习队列，首页显示"今日到期"的数量。

**选项顺序去偏。** 静态题库的正确项原本长期停在第一个位置，学习者可以靠位置记忆连对。现在所有选择题按题目 id 做确定性重排：同一题刷新后顺序不变，但正确项在题目之间分散。判定和错题记录仍用原始下标，逻辑在 `src/engine/optionOrder.ts`。

### 3.3 内容怎么来、怎么校验

词库来自 ECDICT（MIT），构建期转成五个等级分片，共 5805 词，其中 5729 词配了 Tatoeba 的真实例句，词性覆盖率 99.07%。语法、句子、听力、写作、阅读是团队原创。

内容不靠肉眼过一遍。`scripts/validate-content.mjs` 校验词库结构、词性覆盖和题目字段完整性；`src/data/grammar.test.ts` 用分词和 Jaccard 相似度检查"例句不能被直接抄成答案"；`src/data/reading.test.ts` 检查选项标签里不能包含正确答案。这些测试把内容质量问题变成了可以重复执行的检查。

### 3.4 发布门禁

`npm run validate` 是一条串行门禁：类型检查、lint、524 项 Vitest 单元与组件测试（60 个文件）、21 项 Python 内容测试、构建、产物体积预算（初始 JS 不超过 409,600 B，当前 399,279 B，gzip 137,120 B）、21 项 Node 契约测试（Service Worker、离线契约、PWA 资源、设计一致性、启动兜底）、内容校验。任何一项失败都不能发布。

GitHub Actions 在每次推送后跑同一套检查，通过之后部署 Pages。

### 3.5 可用性

六个模块的选择题支持数字键 1–4 选答，Enter 确认或重答，选项上显示数字键帽。图表都提供原生数据表作为替代视图。练习页在 1920×1080 和 1440×900 下可以一屏显示完整题目，不需要滚动。深浅色主题跟随系统，也可以手动切换，练习页和首页共用同一套语义色令牌。

## 六、用起来是什么样

**即开即用。** 不用安装、不用注册，浏览器打开就能学。Chrome、Edge 可以一键装到桌面，iOS 通过"分享 → 添加到主屏幕"安装，装完以独立窗口运行。

**弱网可用。** 离线包和 PWA 缓存让网络条件有限的学校和家庭也能用，机房带宽不够的时候不至于整节课卡在加载上。

**数据在本机。** 没有账号、没有上传、没有埋点。对隐私敏感的用户和未成年人场景来说，这一条比功能数量重要。

**可以继续长。** 学段路线、词库、章节内容都是配置化数据，加学段或语种不需要改交互层；内容校验脚本保证扩展的时候不破坏既有质量。

**方便传播。** 链接自带 1200×630 的分享预览卡，移动端自适应，适合课堂演示和扫码体验。
