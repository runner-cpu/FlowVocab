# FlowVocab 数媒赛参赛方案：赛道推荐与改造计划

> 状态：**方案待确认**。§6 的问题清单等你回复后，才启动 §4/§5 的定向执行；本文档本身只做决策沉淀，不改任何代码。

## 1. 结论先行

- **主推赛道：交互设计类（App/H5）**，申报主题写「智慧教育」。
- **备选赛道：智慧教育与科普创作类**。
- 采用**双备份策略**：P0 阶段（§3）做的调整对两条赛道都有收益；报名截止前按当年官方赛题要求二选一。

推荐逻辑：作品的核心资产是「高完成度的交互式学习应用」——六大训练模块闭环、自适应难度引擎、SM-2 间隔重复调度、错因路由、离线 PWA、章节化星图养成。这套资产与交互设计类的评分逻辑（交互创新、用户体验、技术实现、作品完整度）逐条对齐。智慧教育与科普创作类同样够格，但该赛道的评审更看重教育价值与科普叙事，需要补一轮「教学设计呈现」才能把隐性优势讲出来。

## 2. 竞争力盘点（评审视角）

### 强项

| 资产 | 对评审的意义 |
| --- | --- |
| 六模块闭环：词汇·微光港 / 语法·语法花园 / 句子·桥梁工坊 / 听力·星际电台 / 写作·灵感工作室 / 阅读·故事图书馆 | 作品完整度高，不是单点 demo |
| 自适应难度校准 + SM-2 复习调度（词林） + 错因 10 类路由 + 48 张形近对比卡 | 「智能」有真实机制，不是贴标签 |
| 离线优先 PWA：断网可玩、可安装到桌面/主屏 | 在普遍依赖云端的参赛作品里是清晰差异化，现场演示不怕网络事故 |
| 连击/怒气引擎（5 连击蓄能 3 次双倍经验，刻意无倒计时） + 星尘→能量→星球 11 阶段养成 | 交互记忆点 + 激励设计有教育考量（消除时间焦虑） |
| 成长图谱：热力图（可下钻单日）、六维雷达、难度曲线、星球成长 | 数据可视化直接服务于「学情反馈」 |
| 438 个自动化用例 + `npm run validate` 发布门禁 + CI/CD Pages | 答辩讲「稳定可靠」有硬证据 |
| 内容规模：5805 词（ECDICT）+ 5729 例句（Tatoeba CC-BY 2.0 FR）+ 4 条学段路线（小学/初高中/进阶/四六级） | 内容不是空壳 |

### 弱项 / 风险

1. **教学设计是隐性的**：SM-2、自适应难度、错因路由都实现了，但应用内缺少面向评委的「为什么这样设计」呈现层，教育类赛道会被追问。
2. **美术为 AI 生成插画**：需要按赛事当年规则做 AI 使用披露，或评估替换成本。
3. **内容深度边界**：语音对话仅 6 个场景；CET 路线深层语法节点未全开放；无学习效果对比数据（无后端）。
4. **单机无后端**：没有班级/教师视角，「智慧教育」若被追问落地场景，需以「个人自学场景 + 离线可用」作答并说明边界。

## 3. P0：双赛道兼容调整（确认赛道前做也不亏）

1. **「学习引擎」说明层**：在成长图谱页补一个紧凑面板，用 30 秒讲清四件事——自适应难度如何校准起点、SM-2 如何安排复习窗、错因如何路由到规则卡、连击激励为何取消倒计时。
2. **评委演示动线**：README 固化一条 3 分钟动线（首屏 → 世界地图点亮 → 词汇站答题 → 故意答错看错因卡 → 成长图谱下钻 → 断网刷新演示离线），并强化首访引导与此动线一致。
3. **原创性与素材声明补全**：ECDICT（MIT）/ Tatoeba（CC-BY 2.0 FR）/ Outfit（OFL 1.1）已有 attribution 文件；补 AI 辅助说明与原创承诺要点清单。
4. **内容补强（纯数据层，零架构风险）**：语音对话场景 6 → 10+；错因对比卡增补；根据 P1 赛道结论决定扩写方向。

## 4. P1：按赛道的定向调整（等 §6 确认后执行）

### 若走「交互设计类」

- 首屏 30 秒体验打磨：第一印象权重最高的地方。
- 标志性交互记忆点强化：连击火光 → 星球点亮的因果反馈链做成可感知的闭环。
- 移动端演示复核：评委可能手机扫码，真机过一遍触控目标与动效降级。
- 可选：隐藏「评委速览」模式，一键走完演示动线（需你确认是否要这种演示后门）。

### 若走「智慧教育与科普创作类」

- 「教学设计」呈现层升级：学情闭环可视化（作答数据 → 错因归因 → 复习调度 → 路径调整）。
- 与传统背单词方式的对比叙事：间隔重复参数依据、错因 10 类的分类学出处。
- 教育场景说明：个人自学为主，明确与课堂场景的兼容边界与扩展路径。

## 5. P2：参赛材料（范围等 §6 确认）

- **作品说明书**：按赛道准备两版骨架（交互创新版 / 教育设计版），终稿按确认赛道合并。
- **演示视频分镜脚本**：默认按 3 分钟准备，实际时长以当年通知为准。
- **答辩 PPT 大纲**。
- **原创声明 + 素材来源清单**：现有 licenses 归档已覆盖第三方素材，补 AI 插画披露段。

## 6. 待确认问题（阻塞 P1/P2）

1. **竞赛全称与赛段**：国赛直投 / 省赛 / 校赛？提交截止日期大概什么时候？
2. **赛道最终定哪个**：交互设计类 / 智慧教育与科普创作类 / 双备份到报名前再定？
3. **作品形态硬性要求**：Web App（PWA）是否可直接申报？是否要求微信小程序或原生 App（后者需要移植，工作量约一周起）？
4. **参赛材料准备程度**：全套（说明书 + 视频脚本 + PPT 大纲）/ 只要说明书和视频脚本 / 材料自理？
5. **团队与署名**：几个人参赛？说明书里需要写哪些分工信息？
6. **AI 素材披露口径**：插画为 AI 生成，按当年赛事规则需要声明还是必须替换？

## 7. 排期（确认后启动）

1. **第 1 轮**：P1 定向改造（代码 + 内容），每步过 `npm run validate`。
2. **第 2 轮**：P2 参赛材料成稿。
3. **第 3 轮**：全量验证 + 桌面/移动演示彩排 + 推送 GitHub 并确认 Pages 更新。
