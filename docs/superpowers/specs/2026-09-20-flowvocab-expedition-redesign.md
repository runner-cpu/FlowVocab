# FlowVocab 学习远征地图改版规格

## 目标

把 FlowVocab 从“功能入口集合”升级为一个能持续驱动学习的离线学习远征地图：用户每次打开首页都能看到下一步要做什么、为什么值得做，以及完成后能力会如何成长。保留现有六大训练模块、FSRS/连击/动态难度和 IndexedDB 数据链路，不引入账号、后端、外部 AI API 或联机竞技。

## 设计判断

- 页面类型：离线优先的游戏化学习产品工作台。
- 受众：准备四六级、希望短时高频练习的自学者。
- 视觉语言：冷白/浅灰蓝的清晰底色，湖绿色成长状态，珊瑚橙挑战状态，钴蓝数据状态；训练过程中允许进入深色沉浸区。
- 设计方差：7/10；动效强度：5/10；信息密度：5/10。
- 形状系统：8px 控件、14px 面板、18px 主任务媒体框，不使用无意义的嵌套圆角卡片。
- 字体：系统无衬线字体栈，中文优先使用 PingFang SC/微软雅黑，英文使用 Segoe UI。

## 信息架构

1. 今日远征：今日最佳路线、复习负担、薄弱项推荐、三节点旅程。
2. 训练场：词汇、语法、句子、听力、写作、阅读六个场景入口。
3. 复习牌组：按下一次复习时间和遗忘风险排序的词卡。
4. 成长图谱：六维能力轨迹、学习热力、难度流、星球能量。

现有路由语义保持：`home`、`dashboard`、六个模块 key。导航文案可视觉化调整，但不删除入口。

## 首页模块

- 顶部导航：品牌、学习舱、任务地图、技能训练、成长记录、连续学习和声音开关。
- 任务标题：展示“探索、练习、持续成长”和今日薄弱项补强 CTA。
- 今日任务媒体框：使用 `neon-harbor-quest.png`，左侧显示任务说明和开始按钮，右侧显示今日 XP、连续天数、星球能量。
- 今日旅程：词汇、听力、句子三个节点；从 daily.modules 的真实数据计算完成状态。
- 六种学习场景：基于 MODULE_META 和 progress.radar 计算进度，点击进入实际训练模块。
- 复习回流条：依据 userWords 的 nextReview 显示待复习数量，点击进入词汇模块。

## 成长记录页

- 顶部摘要：累计 XP、最佳连击、今日连击、星球能量和等级。
- 成长提示：以最高能力维度和最低能力维度生成真实推荐。
- 视觉区：雷达图、星球、难度流、90 天热力图，复用已有 ECharts 组件。
- 右侧或顶部操作始终能跳转到薄弱模块，避免图表成为静态装饰。

## 训练场页

- 保留现有模块游戏组件与答题逻辑。
- 增加沉浸式上下文条：返回入口、模块说明、本轮题数、正确率。
- 答题反馈必须仍由 Zustand feedback 驱动，包含命中、连击、暴击、怒气和失误状态。

## 交互与动效

- 主任务、节点、场景卡具备 hover/focus/active 三态；按钮按下时轻微缩放。
- 进度环和能力条使用 CSS transition；首屏区域使用轻微上浮进入动画。
- `prefers-reduced-motion: reduce` 时停用位移动效和重复动画。
- 所有可点击视觉元素使用 button，并保留清晰 focus-visible 描边。

## 响应式

- 桌面：主内容最大 1160px，任务媒体与统计双列，场景三列。
- 平板：任务统计移至主任务下方，场景两列。
- 移动端：单列任务媒体、垂直旅程节点、场景一列，底部固定导航保留安全区间距。

## 数据契约

- 首页只读 `profile`、`planet`、`daily`、`progress.radar`、`userWords`。
- 开始模块调用现有 `go()`；训练组件继续调用 progressStore 的 answer/complete 方法。
- 不在视图层写入模拟数据，不改变 IndexedDB schema。

## 验收清单

- `npm run build` 成功，且 Pages 根目录资源同步。
- `git diff --check` 无错误。
- 浏览器桌面首屏无白屏、无控制台 error；首页 CTA 可进入词汇训练，答题后反馈和统计更新。
- 成长记录页图表正常显示，薄弱项 CTA 可跳转。
- 移动端无横向溢出，底部导航可用。
- 视觉验收覆盖概念图、桌面截图、移动端截图和至少五个关键比较点。
