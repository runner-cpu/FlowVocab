## 1. 技术架构

| 层次 | 方案 | 职责 |
|---|---|---|
| 构建 | Vite 5 + TypeScript | 零配置开发服务器、静态构建 |
| UI 框架 | React 18 (函数组件 + Hooks) | 六大模块与仪表盘界面 |
| 状态管理 | Zustand | 游戏态（连击/怒气/难度）、会话态、UI 态 |
| 数据持久化 | Dexie.js (IndexedDB) | 词库主数据、词库进度、每日统计、会话记录、用户配置 |
| 可视化 | ECharts | 热力图、六维雷达、难度流 |
| 音效反馈 | Web Audio API（合成器） | 连击/暴击/错误音效，零资源零版权 |
| 语音能力 | Web Speech API | 听力模块朗读 + 语音识别跟读（渐进增强） |

**设计原则**：
1. 六大模块共享同一套「心流引擎」（连击/暴击/怒气/动态难度），各自拥有独立玩法形态。
2. 全部数据本地持久化，离线可用，无后端依赖。
3. 路由采用轻量 state 路由（不引入 react-router），减少依赖面。
4. **内容数据驱动**：核心词库为真实大纲数据（开源导入），首次加载懒载入 IndexedDB，离线可用。

## 3. 核心引擎设计

### 3.1 连击 / 暴击 / 怒气引擎（engine/combo.ts）—— v4 修正

**状态**：`combo`（当前连击）、`maxCombo`（本轮最高）、`rageActive`、`rageRemaining`（怒气剩余作答次数）

**判定逻辑**（每次作答触发）：

```
输入：correct(boolean), timeMs(number), medianMs(number)
阈值：fastThreshold = medianMs * 0.7

if correct:
    combo += 1
    isCritical = timeMs < fastThreshold          // 正确且快 = 暴击
    if 攒满 5 连击 且 未处于怒气:                   // 怒气触发
        rageActive = true
        rageRemaining = 3                         // ⚠️ 修正：接下来 3 次作答双倍，不计时
        combo = 0                                 // 连击归零，重新攒下一次怒气
    else if rageActive:
        rageRemaining -= 1                        // 怒气中答对消耗 1 次
else:
    combo = 0                                    // 断连：只归零，不惩罚资源
    rageActive = false; rageRemaining = 0        // 答错怒气结束

产出：
  xp = base * (rageActive ? 2 : 1) * (isCritical ? 2 : 1)
  energy = 1 + combo*0.2 (每连击额外能量)
  反馈事件：{ type: 'hit'|'critical'|'combo'|'rage'|'miss', combo, isCritical, rageActive }
```

**v4 修正说明**：原「30 秒双倍经验」改为「接下来 3 次作答双倍经验」——消除倒计时焦虑，符合「正向延迟满足」设计原则。怒气结束后需重新攒满 5 连击才可再触发（连击在怒气中仍累积，怒气结束不归零；只有触发瞬间归零重新计数）。

**反馈表现**：正确 → 金币飞溅粒子 + "叮"音；暴击 → 屏幕震动 + 打击音；连击 ≥10 → 顶部火焰 + 称号"🔥词汇大师"；怒气激活 → 全屏渐变 + 提示"接下来 N 次作答双倍经验"；错误 → 柔和震动 + 显示正确释义（不扣资源）。

### 3.2 动态难度阀门（engine/difficulty.ts）—— 不变

**滑动窗口**：最近 10 次作答结果 `window[]`（正确/错误 + 用时）

```
accuracy = 窗口内正确数 / 10
slowRatio = 窗口内"超慢"占比（用时 > median*1.4）

if accuracy > 0.85 and slowRatio < 0.4:  level+1   (上限 4)
if accuracy < 0.60 or slowRatio > 0.6:   level-1   (下限 0)
else: level 保持

难度档位 0-4：CET4 基础 → CET4 进阶 → CET6 入门 → CET6 进阶 → CET6 高阶
可视化：档位对应主题色 绿 → 蓝 → 紫 → 金 → 火红
```

难度对用户的呈现：仅显示"难度色阶 + 挑战升级提示"，不暴露算法。

### 3.3 遗忘曲线调度（engine/forget.ts）—— 不变

```
质量评分 q ∈ {0,1,2}（答错=0，对但慢=1，快而准=2）
interval: [1, 3, 7, 15, 30] 天 下标 = min(q, 2)
nextReview = lastReview + interval 天
词状态机：new → learning → mastered（连续 3 次质量≥1 升 mastered）
```

### 3.4 音效合成（engine/audio.ts）—— 不变

Web Audio API 合成，无外部资源：hit（660Hz/80ms）、critical（880+1320Hz 双音）、combo（音高随连击递增）、rage（上行琶音）、miss（200Hz 柔和低音）；禅模式可静音。

## 5. 六大技能模块详细设计

> 每个模块的"产出"统一汇入养成系统能量与六维雷达分数。

### 5.1 词汇 · 词魂战场（components/modules/vocab）—— P0 完整

**数据模型**：
```ts
interface Word { id: string; word: string; phonetic: string; meaning: string;
                 example: string; exampleCn: string; level: 0|1|2|3|4; pos: string;
                 source?: 'cet4'|'cet6'; phrases?: { phrase: string; translation: string }[] }
```
- 词库 13159 词（真实大纲数据），按 level 分 5 档；词状态存 `userWords` 表。
- 干扰项由 `buildVocabOptions` 从词池随机取 3 个不同释义生成。

**玩法**：展示单词 → 四选一选正确释义。答对/答错进引擎（连击/暴击/怒气/动态难度全生效）。
**出题**：优先抽取 `status=new` 或 `nextReview<=today` 的词，按动态难度 level 过滤。
**反馈**：正确答案高亮 + 释义 + 词组展示。

### 5.2 语法 · 技能树（components/modules/grammar）—— P0 完整

**数据模型**：
```ts
interface SkillNode { id: string; name: string; parent?: string; desc: string;
                      examples: string[]; quizzes: GrammarQuiz[] }
interface GrammarQuiz { prompt: string; options: string[]; answer: number; explain: string }
```
**技能树**：时态语态 / 定语从句 / 名词性从句 / 非谓语动词 / 虚拟语气 五分支 × 3 节点。
**玩法**：技能树可视化 → 点击节点 → 完成 3 道题 → 全对点亮节点（前置解锁）。

### 5.3 句子 · 拆解工坊（components/modules/sentence）—— P0 完整

**数据模型**：
```ts
interface SentenceQuest {
  id: string; type: 'puzzle'|'translate';
  sentence: string; segments: { text: string; bucket: 'main'|'clause'|'modifier' }[];
  prompt: string; options: string[]; answer: number; explain: string;
}
```
**玩法 A 拼图**：长难句拆碎片 → 拖入「主干/从句/修饰」三桶，全对通过。
**玩法 B 翻译**：四选一最佳译文（限时，超时按错误计）。

### 5.4 听力 · 听写工坊（components/modules/listening）—— P0 框架（v4 修正）

**数据模型**：
```ts
interface ListeningItem { id: string; text: string; level: number;
                          blanks: { index: number; answer: string; options: string[] }[] }
```
**主模式·跟读逐词匹配（v4 修正，需浏览器语音识别）**：
```
① Web Speech Synthesis 播放原句
② 用户点击「开始跟读」，对着麦克风朗读
③ SpeechRecognition 返回识别文本
④ 前端逐词 Levenshtein 匹配（距离 ≤1 视为命中，容错拼写/时态）
⑤ 读对的词变绿、读错/漏读的变红 → 命中率 ≥60% 点亮本句
```
> 修正说明：原「波形实时音准」方案 Web Speech API 无法实现，改为「识别文本逐词匹配点亮」，同样直观且纯前端 100% 可实现。

**降级模式**：浏览器不支持语音识别时，回退为「挖空选词」（听音辨词，四选一填空）。

### 5.5 写作 · 句型工坊（components/modules/writing）—— P0 框架（v4 修正）

**数据模型**：
```ts
interface WritingTask {
  id: string; title: string; type: 'sort'|'error';
  prompt: string;              // 题干
  segments?: string[];         // sort：正确顺序的片段（UI 打乱）
  sentence?: string;           // error：含错误句子
  options?: string[]; answer?: number; explain?: string;
}
```
**玩法**（8 题：4 排序 + 4 改错）：
- **排序题**：打乱的句子片段按正确语序点击排列（训练倒装/强调/非谓语等高频句型）。
- **改错题**：展示含错误句子 + 4 个改写选项，选出正确改法（训练主谓一致/比较级/介词+动名词等高频错误）。
- 答对得 5 星计入写作维度；P2 再接入 LLM 开放式批改。
> 修正说明：开放式写作规则批改易被钻空子且体验不稳定，P0 改为客观题化。

### 5.6 阅读 · 叙事副本（components/modules/reading）—— P0 框架

**数据模型**：
```ts
interface NarrativeNode { id: string; text: string; choices: { label: string;
                          next: string; quiz?: ReadingQuiz }[] }
interface ReadingQuiz { prompt: string; options: string[]; answer: number; explain: string }
interface Chapter { id: string; title: string; intro: string; start: string; nodes: Record<string, NarrativeNode> }
```
**玩法**：章节制原创故事 → 阅读剧情 → 关键节点「考点题」（答对才能继续）→ 分支推进 → 完成章节。

## 6. 养成系统 · 词汇星球（components/dashboard 与 Home）

- `energy`：全局能量，由所有模块产出累加。
- 星球阶段 0-5：`level = floor(energy / 50)`，CSS 绘制（径向渐变球体 + 轨道 + 光晕）。

- 每日目标：`dailyTargetXp`（默认 100），达成后今日热力格子亮金。

## 10. 验收标准（v4.0）

1. 一轮 30 题词汇会话：暴击/连击/怒气至少各触发 1 次，反馈延迟 <0.3s。
2. 动态难度：10 题窗口 >85% 升档（色阶+词档），<60% 降档。
3. 词库：13159 词（CET4+CET6）懒加载入 IndexedDB，离线可用；加载失败降级示例词库。
4. 怒气机制：5 连击触发 → 接下来 3 次作答双倍 → 消耗完/答错结束 → 重新攒 5 连击再触发（已单测覆盖）。
5. 听力主模式（语音识别可用）：跟读 → 逐词绿/红点亮；降级模式：挖空选词。
6. 写作：8 题排序/改错客观题，答对得星计入写作维度。
7. 六模块均可完成一次完整练习并产出数据；刷新后进度完整保留。
8. 480px 宽可流畅操作。
